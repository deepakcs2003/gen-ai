Project Overview

This is a real-world AI application that solves a critical business problem: helping equity research analysts quickly extract insights from massive amounts of financial news articles.

The Business Problem

Who needs this?

  • Equity Research Analysts (like those at HDFC Mutual Fund, JP Morgan, Goldman Sachs)
  • Investment Firms

  1. Read 50+ news articles from MoneyControl, Economic Times, Bloomberg
  2. Analyze quarterly reports, earnings calls, financial statements

Reading and finding specific information across hundreds of articles is incredibly time-consuming. He might spend hours looking for answers like:

  • "What is Tata Motors' profit margin this quarter?"
  • "How many Tata Nano cars were sold last month?"

    • Inefficient workflow
  2. No Aggregate Knowledge Base

  3. Token/Word Limits
    • ChatGPT has input size restrictions
    • Can't paste very long articles
    • Limited context window

Our Solution Architecture

We're building a smart system that:

  1. Automatically loads articles from news websites
  2. Creates a searchable knowledge base (Vector Database)
  3. Answers questions in natural language with source citations

Core Concepts Explained (Theory Deep Dive)

1. Document Chunking - Why Split Articles?

The Problem

LLMs have token limits (like 4,000 tokens for GPT-3.5). One article might be 10,000 tokens!

Example Scenario

Article about Nvidia: 10,000 tokens
Question: "What is Nvidia's operating margin?"
Answer is in: First 500 tokens only!

Inefficiency: Why send all 10,000 tokens to the API when the answer is in the first 500?

  • Costs more money (OpenAI charges per token)
  • Slower response
  • Wastes context window

The Solution: Smart Chunking

Step 1: Break into manageable pieces

Original Article (10,000 tokens)
↓
Chunk 1: 500 tokens (contains operating margin)
Chunk 2: 500 tokens (about GPU products)
Chunk 3: 500 tokens (about competitors)
... and so on

Step 2: Only send relevant chunks
When asked "What is Nvidia's operating margin?", our system:

  1. Identifies Chunk 1 is relevant
  2. Sends only Chunk 1 to the LLM
  3. Saves 95% of token costs!

2. Semantic Search vs Keyword Search

Keyword Search (Old Way)

# Simple Ctrl+F style search
if "H100 GPU price" in article:
    return article

Problem: What if the article says "cost of H100 graphics processor"?

  • Different words, same meaning
  • Keyword search **FAILS**!

Semantic Search (Our Way)

Example 1: The Apple Problem

Query 1: "calories in apple"
Query 2: "revenue of Apple"

Both contain "apple", but:

  • First = 🍎 Fruit
  • Second = 🍏 Company

How does semantic search know?
It looks at context and meaning, not just words!

How Semantic Search Works

Word/Sentence Embeddings:
Convert text into mathematical vectors that capture meaning.

"calories in apple" → [0.2, 0.8, 0.1, ..., 0.4] (768 numbers)
                          ↓
                          Points toward "food/nutrition" in vector space

"revenue of Apple" → [0.7, 0.1, 0.9, ..., 0.3] (768 numbers)
                          ↓
                          Points toward "business/finance" in vector space

Similar meanings = Similar vectors (mathematically close in space)

3. Vector Databases - Fast Similarity Search

The Challenge

You have 1 million article chunks converted to embeddings. How do you quickly find the 3 most relevant chunks?

Naive approach: Compare your question to all 1 million chunks = **SLOW** ⏱️

Vector Database Solution (FAISS)

FAISS (Facebook AI Similarity Search) creates special data structures that allow:

  • Fast similarity search (milliseconds instead of seconds)
  • Approximate nearest neighbors (finds closest matches efficiently)

Think of it like:

  • Google Maps organizing locations geographically
  • FAISS organizes embeddings by "meaning proximity"

4. Retrieval Methods: Stuff vs Map-Reduce

Stuff Method (Simple)

Process:

  1. Get relevant chunks: [Chunk 2, Chunk 4]
  2. Combine them into ONE prompt
  3. Send to LLM once
  4. Get answer
Prompt: "Based on this text: [Chunk 2 + Chunk 4], 
          what is the H100 GPU price?"

Pros:

  • Simple
  • One API call (cheaper)

Cons:

  • If chunks combined > token limit, **FAILS**!

Map-Reduce Method (Advanced)

Process:

  1. Get relevant chunks: [Chunk 1, Chunk 2, Chunk 3, Chunk 4]
  2. Ask question to EACH chunk separately (4 API calls)
  3. Combine answers (5th API call)
Call 1: "What is H100 price? Based on: [Chunk 1]" → Answer 1
Call 2: "What is H100 price? Based on: [Chunk 2]" → Answer 2
Call 3: "What is H100 price? Based on: [Chunk 3]" → Answer 3
Call 4: "What is H100 price? Based on: [Chunk 4]" → Answer 4

Call 5: "Given these answers: [A1, A2, A3, A4], 
          what's the final answer?" → Final Answer

Pros:

  • Handles large contexts
  • No token limit issues

Cons:

  • 5 API calls = More expensive
  • Slower

"""
News Research Tool - AI-Powered Article Analysis System
Uses Google Gemini API instead of OpenAI
Updated for latest LangChain library structure
"""

import os
import streamlit as st
import pickle
import time
from dotenv import load_dotenv

# Updated LangChain imports for new library structure
from langchain_google_genai import GoogleGenerativeAI, GoogleGenerativeAIEmbeddings
from langchain.chains import RetrievalQAWithSourcesChain
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import UnstructuredURLLoader
from langchain_community.vectorstores import FAISS

# CONFIGURATION

# Load environment variables from .env file
load_dotenv()

# File path for storing the FAISS vector database
FAISS_STORE_PATH = "faiss_store_gemini.pkl"

# INITIALIZE GOOGLE GEMINI LLM

# Get API key from environment
google_api_key = os.getenv("GOOGLE_API_KEY")

# Initialize Gemini model
# Using gemini-pro which is suitable for text generation
llm = GoogleGenerativeAI(
    model="gemini-pro",
    google_api_key=google_api_key,
    temperature=0.3,  # Lower = more focused, Higher = more creative
    max_output_tokens=1024  # Maximum response length
)

# Initialize Gemini Embeddings
# This converts text into vector representations
embeddings = GoogleGenerativeAIEmbeddings(
    model="models/embedding-001",
    google_api_key=google_api_key
)

# STREAMLIT UI SETUP

# Main page title
st.title("📰 News Research Tool with Gemini AI")
st.markdown("*Powered by Google Gemini - Extract insights from financial news articles*")

# Sidebar for URL inputs
st.sidebar.title("News Article URLs")
st.sidebar.markdown("Enter up to 3 article URLs to analyze")

# Create 3 URL input fields
urls = []
for i in range(3):
    url = st.sidebar.text_input(
        f("URL {i+1}"),
        placeholder=f("https://example.com/article-{i+1}")
    )
    if url:  # Only add non-empty URLs
        urls.append(url)

# Process URLs button
process_url_clicked = st.sidebar.button("🔄 Process URLs")

# Placeholder for status messages
main_placeholder = st.empty()

# DOCUMENT PROCESSING PIPELINE

if process_url_clicked and urls:
    try:
        # STEP 1: Load data from URLs
        main_placeholder.text("📥 Loading data from URLs...")
        loader = UnstructuredURLLoader(urls=urls)
        documents = loader.load()
        
        st.sidebar.success(f("✅ Loaded {len(documents)} articles"))
        
        # STEP 2: Split documents into chunks
        main_placeholder.text("✂️ Splitting documents into chunks...")
        
        # RecursiveCharacterTextSplitter splits intelligently
        # It tries separators in order: \n\n, \n, space
        text_splitter = RecursiveCharacterTextSplitter(
            separators=['\n\n', '\n', '.', ','],  # Split by paragraphs first
            chunk_size=1000,  # Each chunk ~1000 characters
            chunk_overlap=200  # 200 char overlap for context continuity
        )
        
        docs = text_splitter.split_documents(documents)
        st.sidebar.info(f("📄 Created {len(docs)} text chunks"))
        
        # STEP 3: Create embeddings and build vector store
        main_placeholder.text("🧠 Building embeddings (this may take a minute)...")
        
        # Convert all chunks to vectors and store in FAISS
        vectorstore = FAISS.from_documents(docs, embeddings)
        
        # STEP 4: Save to disk for persistence
        main_placeholder.text("💾 Saving vector database...")
        with open(FAISS_STORE_PATH, "wb") as f:
            pickle.dump(vectorstore, f)
        
        main_placeholder.success("✨ Processing complete! Ready to answer questions.")
        time.sleep(2)
        main_placeholder.empty()
        
    except Exception as e:
        st.error(f("❌ Error processing URLs: {str(e)}"))
        st.info("💡 Tip: Make sure URLs are accessible and contain text content")

# QUESTION ANSWERING INTERFACE

# Question input box
query = st.text_input(
    "❓ Ask a question about the articles:",
    placeholder="E.g., What is the price of Tiago iCNG?"
)

if query:
    # Check if vector database exists
    if os.path.exists(FAISS_STORE_PATH):
        try:
            # Load the vector database
            with open(FAISS_STORE_PATH, "rb") as f:
                vectorstore = pickle.load(f)
            
            # Create retrieval chain
            # This chain retrieves relevant chunks and generates answers
            chain = RetrievalQAWithSourcesChain.from_llm(
                llm=llm,
                retriever=vectorstore.as_retriever(
                    search_kwargs={"k": 3}  # Retrieve top 3 most relevant chunks
                )
            )
            
            # Get answer with sources
            with st.spinner("🤔 Thinking..."):
                result = chain({"question": query}, return_only_outputs=True)
            
            # Display answer
            st.header("💡 Answer")
            st.write(result["answer"])
            
            # Display sources
            sources = result.get("sources", "")
            if sources:
                st.header("📚 Sources")
                sources_list = sources.split("\n")
                for source in sources_list:
                    if source.strip():
                        st.markdown(f("- {source}"))
            
        except Exception as e:
            st.error(f("❌ Error answering question: {str(e)}"))
    else:
        st.warning("⚠️ Please process URLs first using the sidebar!")

# ===================================================================
# INFORMATION PANEL

with st.expander("ℹ️ How to use this tool"):

"""
WHAT ARE EMBEDDINGS?

Embeddings convert text into vectors (arrays of numbers) that capture MEANING.

Key Concept: Similar meanings → Similar vectors

Example:
    "king" - "man" + "woman" ≈ "queen"
    
This works because embeddings capture relationships!
"""

# Initialize embeddings

    model="models/embedding-001",
    google_api_key=os.getenv("GOOGLE_API_KEY")

# Example sentences
sentences = [
    "The cat sat on the mat",
    "A feline rested on the rug",
    "The dog played in the park",
    "Python is a programming language"
]

print("\n📊 Embedding Examples:")

# Get embeddings for all sentences
embedded_sentences = []
for sentence in sentences:
    vec = embeddings.embed_query(sentence)
    embedded_sentences.append(vec)
    print(f("\nSentence: '{sentence}'"))
    print(f("Vector dimensions: {len(vec)}"))
    print(f("First 5 numbers: {vec[:5]}"))


# Demonstrating Semantic Similarity
from numpy import dot
from numpy.linalg import norm

def cosine_similarity(vec1, vec2):
    """Calculate how similar two vectors are (0 to 1)"""
    return dot(vec1, vec2) / (norm(vec1) * norm(vec2))

print("\n🔍 Semantic Similarity Scores (0=different, 1=identical):")
print(f("\nSentence 1: '{sentences[0]}'"))
print(f("Sentence 2: '{sentences[1]}'"))
sim_12 = cosine_similarity(embedded_sentences[0], embedded_sentences[1])
print(f("Similarity: {sim_12:.4f} ← High! (Same meaning, different words)"))

print(f("\nSentence 1: '{sentences[0]}'"))
print(f("Sentence 3: '{sentences[2]}'"))
sim_13 = cosine_similarity(embedded_sentences[0], embedded_sentences[2])
print(f("Similarity: {sim_13:.4f} ← Lower (Different topics)"))

print(f("\nSentence 1: '{sentences[0]}'"))
print(f("Sentence 4: '{sentences[3]}'"))
sim_14 = cosine_similarity(embedded_sentences[0], embedded_sentences[3])
print(f("Similarity: {sim_14:.4f} ← Lowest (Completely unrelated)"))

print("\n💡 Key Insight:")
print("Sentences 1 and 2 have NO common words, but high similarity!")
print("This is the power of semantic embeddings.")

print("=" * 80)

"""
THE CHALLENGE:

Imagine you have 1,000,000 article chunks embedded as vectors.
User asks a question → You embed the question → Now what?

Naive approach: Compare question vector to ALL 1 million vectors
Problem: Takes forever! ⏱️

FAISS Solution: Special data structures for fast approximate search
Think: Google Maps doesn't check every road, it's smart about it!
"""

import faiss
import numpy as np

# Create sample vectors (simulating article chunks)
dimension = 768  # Gemini embedding dimension
num_vectors = 10000  # Imagine 10,000 article chunks

# Generate random vectors (in real app, these are from embeddings)
np.random.seed(42)
vectors = np.random.random((num_vectors, dimension)).astype('float32')

print(f("\n📚 Dataset: {num_vectors:,} vectors of dimension {dimension}"))

# Create FAISS index
index = faiss.IndexFlatL2(dimension)  # L2 = Euclidean distance
index.add(vectors)

print(f("✅ Index created with {index.ntotal:,} vectors"))

# Search for similar vectors
query_vector = np.random.random((1, dimension)).astype('float32')

import time

start = time.time()
distances, indices = index.search(query_vector, k=5)  # Find 5 nearest
end = time.time()

print("\n🔍 Search Results:")
print(f("Found 5 most similar vectors in {(end-start)*1000:.2f} milliseconds!"))
print(f("Indices: {indices[0]}"))
print(f("Distances: {distances[0]}"))

print("\n💡 In our news research tool:")
print("1. User asks: 'What is Tiago price?'")
print("2. Convert question to vector")
print("3. FAISS finds most relevant article chunks (fast!)")
print("4. Send only those chunks to Gemini")
print("5. Get accurate answer")
